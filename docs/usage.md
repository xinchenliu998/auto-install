# 使用说明

> 本文说明如何运行 auto-install、如何配置、以及产物（配置与日志）落在哪里。
> 开发相关（新增软件、脚本约定）见 [`development.md`](development.md)。

---

## 一、运行方式

| 方式 | 说明 |
| --- | --- |
| `auto-install.au3` | 有 AutoIt v3 环境时，直接双击或用 AutoIt 运行 |
| `auto-install.exe` | 编译后的独立可执行文件，目标机器**无需安装 AutoIt** |

> 编译时请选择 **x64**，否则 `@ProgramFilesDir` 会指向 `Program Files (x86)`，导致安装结果校验失败。

### 典型流程

1. 把整个项目拷贝到工控机本地目录（建议非系统盘，如 `D:\auto-install`）。
2. 把各软件的安装包放进 `packages/<软件名>/` 对应目录（也可以放在别处，在配置界面改「安装包目录」即可）。
3. 运行总入口，在配置界面完成设置：安装根目录、安装包目录，必要时再配「拷贝源/目标目录」。
4. 点击「开始安装」，等待执行完成。
5. 根据日志核对结果，必要时重启机器。

> **安装包目录不在版本库里**：整个 `packages/` 目录都不纳入 git —— 安装包体积普遍较大，
> 部分单个安装包就超出代码托管平台的单文件上限；而且该目录本身可配置、可以放在仓库之外。
> 从仓库克隆后需自行创建该目录并放入安装包，或在配置界面把「安装包目录」指到别处。
> 文件名见 `docs/packages/` 下对应文档的「基本信息」表。

## 二、配置界面

### 基本配置

| 项 | 说明 |
| --- | --- |
| **软件名称** | 默认 `auto-install`。用于生成默认安装根目录，同时作为日志与状态标识。不能包含 `\` `/` `:` 等路径字符。 |
| **安装根目录** | 默认 `%LOCALAPPDATA%\BJ\<软件名称>`（`BJ` 为公司名称）。可手动修改，或点「浏览...」选择目录。旁边「默认」按钮可恢复默认模板并重新跟随软件名称。 |
| **安装包目录** | 安装包所在目录，默认 `packages`。**可以填相对路径或绝对路径**（见下）。右侧「刷新」按当前目录重新扫描软件列表。 |
| **拷贝源目录** | 要部署到目标机器的资源文件夹（出厂文档、驱动等）。**留空则不执行拷贝**。 |
| **拷贝目标目录** | 拷贝源目录会被**整体**拷贝到该目录下的同名子目录。**留空则使用安装根目录**。 |

「基本配置」组下方有四行灰色提示，始终可见：

| 提示行 | 内容 |
| --- | --- |
| **实际路径** | 安装根目录把 `%LOCALAPPDATA%` 等环境变量展开后的真实路径，随输入实时刷新 |
| **安装包目录** | 安装包目录解析后的绝对路径（相对路径会拼到本程序所在目录下） |
| **日志文件** | 本次运行将要写入的日志文件完整路径 |
| **配置文件** | `config.ini` 的保存位置（固定不变，鼠标悬停可看完整路径） |

> 保存配置时，状态栏只提示「配置已保存」，具体保存到哪个文件看上面「配置文件」那一行即可。

> **关于自动跟随**：修改软件名称时，安装根目录会自动同步；一旦你手动改过安装根目录，
> 就停止跟随，避免覆盖你的输入。点「默认」可重新开启跟随。

> **关于环境变量**：安装根目录保存的是**含环境变量的模板**（如 `%LOCALAPPDATA%\BJ\auto-install`），
> 换机器、换账户后依然可用。也支持手工填入其它环境变量。

> **为什么用 Local 而不是 Roaming**：`%APPDATA%` 指向 Roaming 目录，会随域账户漫游同步到其它机器，
> 把安装文件放进去既拖慢登录、又可能造成版本混乱。`%LOCALAPPDATA%` 只属于本机，更适合放绿色工具、
> 日志等运行产物。基准位置由 `Include/Constants.au3` 的 `$ENV_INSTALL_BASE` 决定，改一行即可整体切换。

### 安装包目录：与项目解耦

**安装包目录**支持两种写法：

| 写法 | 示例 | 解析结果 |
| --- | --- | --- |
| 相对路径 | `packages` | `<本程序所在目录>\packages` —— 即「启动程序同级」，也是默认值 |
| 绝对路径 | `D:\装机包` | 原样使用 |
| 含环境变量 | `%USERPROFILE%\装机包` | 先展开环境变量再判断 |

所以可以把安装包放在完全独立的位置（比如移动硬盘、网络共享、另一个仓库），
程序本体和安装包互不绑定。

**切换安装包目录后会自动重新扫描**：点「浏览...」选好目录，或手动改完路径后点「刷新」，
软件列表会立即按新目录重填（窗口大小与控件位置都不变）。
**原来已勾选的软件如果在新目录里仍然存在，勾选状态会保留**；新出现的软件默认勾选。

### 资源拷贝（文档部署）

填了**拷贝源目录**后，执行时会多一项「拷贝资源」任务：

```
<拷贝源目录>   ->   <拷贝目标目录>\<源文件夹名>\
```

- 整个文件夹**原样搬过去**，目录结构完整保留。
- 目标是**覆盖式**拷贝（用 `robocopy /E` 实现），重复执行不会报错。
- 拷贝目标留空时，默认拷到**安装根目录**下。

例如源目录 `D:\出厂文档`、目标目录留空，结果是
`%LOCALAPPDATA%\BJ\auto-install\出厂文档\`。

> 拷贝源目录当前不存在时不会中断执行，日志里会记录一条错误并计入「失败」。

### 选择要安装的软件

软件列表由**安装包目录**下的子目录**自动扫描**得出，无需手工维护。
列表是一份带复选框的清单，点复选框即可勾选 / 取消。

- 工具条：**全选** / **全不选** / **反选**，右侧显示「已选 N / M」计数。
- 列表**高度固定**（约 8 行），软件多了由列表自带的**滚动条**浏览 ——
  窗口大小和控件位置都不会随软件数量变化。
- 目录下没有任何软件子目录时，列表里会显示一行灰色提示。
- 每个条目显示的是软件的**显示名**（来自 `package.ini` 的 `DisplayName`，没有则用目录名）；
  当前解析出的安装包绝对路径见上方「安装包目录」那一行灰色提示。

### 底部操作

| 按钮 | 行为 |
| --- | --- |
| **开始安装** | 校验并保存配置，然后进入执行界面，按勾选项依次执行 |
| **保存配置** | 只保存到 `config.ini`（路径见「基本配置」组内的「配置文件」一行），不执行安装 |
| **退出** | 关闭窗口，不保存 |

左下角显示当前权限状态（管理员 / 普通用户），鼠标悬停可看说明。

## 三、命令行参数

| 参数 | 说明 |
| --- | --- |
| 无参数 | 打开配置界面（默认） |
| `--run` | 跳过配置界面，直接按 `config.ini` 执行安装 |
| `--auto-close` | 配合 `--run` 使用，执行结束后自动关闭，适合无人值守 / 批处理调用 |
| `--help` | 显示帮助 |

示例：

```bat
auto-install.exe --run --auto-close
```

**退出码**：全部成功为 `0`；存在失败项为 `1`。可在批处理里据此判断。

> 无人值守模式下（`--run`）不会弹出提权询问，请提前确保以管理员权限运行。

## 四、权限与提权

- 部分软件需要写入 `Program Files`、注册表或系统 `PATH`，**需要管理员权限**。
- 配置界面本身不需要管理员权限，只有在点「开始安装」时才会检查。
- 若检测到未提权，会弹窗询问是否以管理员身份重新启动：
  - 选「是」：先保存配置，再以 `runas` 方式带 `--run` 参数重启，自动继续执行；
  - 选「否」：以当前权限继续执行，日志中会给出警告，部分任务可能失败。
- 无人值守模式（`--run`）下不弹窗，直接以当前权限执行并在日志中记录警告。

## 五、配置文件

### config.ini

位于脚本同级目录，**首次运行自动生成**。

```ini
[General]
SoftwareName=auto-install
InstallRoot=%LOCALAPPDATA%\BJ\auto-install
PackagesDir=packages
CopySourceDir=
CopyDestDir=

[Packages]
7zip=1
SQLite3=1
Sublime Text=1
everything=1
halcon=1
wps=1
HslCommunicationDemo=1
DBX=1
```

| 段 / 键 | 说明 |
| --- | --- |
| `[General] SoftwareName` | 软件名称 |
| `[General] InstallRoot` | 安装根目录（可含环境变量的模板） |
| `[General] PackagesDir` | 安装包目录；相对路径相对本程序解析，默认 `packages` |
| `[General] CopySourceDir` | 资源拷贝源目录；留空表示不拷贝 |
| `[General] CopyDestDir` | 资源拷贝目标目录；留空表示用安装根目录 |
| `[Packages] <目录名>` | 该软件是否默认勾选，`1` 勾选 / `0` 不勾选 |

- `[Packages]` 段由**安装包目录**的扫描结果自动维护，**新增软件会自动以 `1` 出现**。
- 也可以直接编辑本文件做批量预设，例如把 `wps` 改成 `0` 让它默认不勾选。
- 想恢复默认，删除 `config.ini` 即可（`[General]` 里只有 `SoftwareName` 是必填的，其余留空即用默认值）。

### package.ini（可选）

在**安装包目录**下的 `<软件目录>/` 里放一份 `package.ini`，可指定配置界面里显示的名称：

```ini
[Package]
DisplayName=WPS Office
```

不提供时，直接显示目录名。

## 六、执行日志

- **位置**：`<安装根目录>\logs\install_<时间戳>.log`，UTF-8 编码。
- **内容**：每行形如 `[2026-10-06 19:06:54] [INFO ] 消息`，级别有
  `INFO` / `OK` / `WARN` / `ERROR` / `STEP`。
- 执行界面上的日志框会**实时**同步显示同样的内容，点「打开日志目录」可直接定位到日志所在文件夹。

### 等待心跳（界面长时间没动静 ≠ 卡死）

安装 / 解压 / 拷贝耗时较长时，程序**仍在正常工作**，只是那一步没有新内容可打印。
为便于观察，等待期间会持续输出心跳：

- 执行界面顶部的信息标签**每秒刷新**，显示如 `DBX 安装，已等待 3 分 20 秒 ...`；
- 日志里每 10 秒补一条 `XXX 仍在进行，已等待 3 分 20 秒`。

**只要计时还在往上走，就说明任务在正常执行，不必强行结束进程。**
界面在等待期间本身也是响应的（可以移动窗口、点「打开日志目录」），不会假死。

心跳间隔由 `Include/Constants.au3` 的 `$RUN_HEARTBEAT_MS`（界面刷新）与
`$RUN_HEARTBEAT_LOG_SEC`（写日志）控制。

### 结果汇总

执行结束时日志会给出汇总，执行界面顶部也会提示：

```
成功 N 项  |  跳过 M 项  |  失败 K 项
```

| 状态 | 含义 |
| --- | --- |
| **成功** | 安装/解压完成并通过结果校验；**已经装好、无需处理的也计入这里**（日志里会写「已检测到 X，跳过安装」） |
| **跳过** | 该软件尚未实现安装脚本（日志会提示需要补的模块名） |
| **失败** | 安装包缺失、启动失败、超时，或装完未通过结果校验 |

执行顺序是：**先按勾选依次安装软件，最后执行资源拷贝**（若配置了拷贝源目录）。
资源拷贝会作为一项独立任务出现在进度与汇总里。

### 已安装检测

每个软件在动手之前都会先判断是否已经装过，判断范围是：

1. 该软件的**预期安装路径**（如 `C:\Program Files\7-Zip\7z.exe`）；
2. **整个系统 `PATH`** —— 覆盖「装在别的盘 / 其它目录」或「绿色版已经挂在 `PATH` 上」的情况。

任一命中就视为已安装，直接跳过、不重复安装，并计入「成功」。日志里会打印实际找到的位置。

## 七、常见问题

**Q：点了「开始安装」但某个软件直接「跳过」了？**
该软件还没有对应的安装脚本。按日志提示在 `Include\Install\` 下补一个模块，并在 `All.au3` 的模块列表登记，见 [`development.md`](development.md)。

**Q：日志显示「安装超时，已强制结束」？**
单个软件默认超时 10 分钟（WPS 为 30 分钟）。安装包体积大或机器较慢时可能不够，
可在 `Include\Constants.au3` 中调整 `$TIMEOUT_INSTALL` / `$TIMEOUT_INSTALL_LONG`。

**Q：某个软件安装了很久，界面没动静，是卡死了吗？**
通常不是。等待期间界面顶部会显示「XXX 安装，已等待 X 分 Y 秒 ...」并**每秒刷新**，
日志里每 10 秒也会补一条「仍在进行」。**计时在走 = 程序在工作**。
真正卡死的表现是：计时**停止不动**、窗口无法移动、点按钮没反应 —— 那才需要处理。

**Q：装完提示「未找到 xxx」？**
说明安装程序返回了成功，但在**预期路径和整个系统 `PATH`** 里都没找到主程序。
请核对 `docs/packages/` 下该软件文档的「脚本实现」一节，以及安装包版本是否与脚本常量一致。

**Q：日志说「已检测到 X，跳过安装」，但汇总里算成了「成功」？**
这是正常的。已经装好的软件无需再处理，属于「处理完成」，所以计入成功；只有**没有安装脚本**的软件才计入「跳过」。

**Q：想换一个版本的安装包？**
替换安装包目录下 `<软件目录>/` 里的文件后，同步修改 `Include/Install/<软件>.au3` 顶部的安装包文件名常量，
并更新 `docs/packages/` 下对应的说明文档。

**Q：软件列表是空的 / 少了几个软件？**
列表是扫描**安装包目录**下的子目录得出的。先看「基本配置」组里「安装包目录」那一行灰色提示，
确认解析出的绝对路径对不对；再确认该目录下确实有以软件名命名的子目录。
改完路径后记得点右侧「刷新」。

**Q：改了安装包目录，勾选会不会丢？**
不会。重新扫描时，**在新目录里仍然存在的软件会保留原来的勾选状态**，新出现的软件默认勾选。

**Q：拷贝资源没执行？**
「拷贝源目录」留空就不会执行。填了之后，日志里会出现一项「拷贝资源」任务，
写明了源目录与目标目录，可以据此核对。
