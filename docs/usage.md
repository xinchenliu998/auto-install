# 使用说明

> 本文说明如何运行 auto-install、如何配置、以及产物（配置与日志）落在哪里。
> 开发相关（新增软件、脚本约定）见 [`development.md`](development.md)。

---

## 一、运行方式

| 方式 | 说明 |
| --- | --- |
| `auto-install.au3` | 有 AutoIt v3 环境时，直接双击或用 AutoIt 运行 |
| `auto-install.exe` | 编译后的独立可执行文件，目标机器**无需安装 AutoIt** |

> 编译时请选择 **x64**，否则 `@ProgramFilesDir` 会指向 `Program Files (x86)`，导致安装结果校验失败。

### 典型流程

1. 把整个项目拷贝到工控机本地目录（建议非系统盘，如 `D:\auto-install`）。
2. 把各软件的安装包放进 `packages/<软件名>/` 对应目录（也可以放在别处，在配置界面改「安装包目录」即可）。
3. 运行总入口，在配置界面完成设置：安装根目录、安装包目录，必要时再配「拷贝源/目标目录」。
4. 点击「开始安装」。程序会先做一遍**前置检查**（见第六节），通过后再依次安装勾选的软件。
5. 根据日志核对结果，必要时重启机器。

> **安装包目录不在版本库里**：整个 `packages/` 目录都不纳入 git —— 安装包体积普遍较大，
> 部分单个安装包就超出代码托管平台的单文件上限；而且该目录本身可配置、可以放在仓库之外。
> 从仓库克隆后需自行创建该目录并放入安装包，或在配置界面把「安装包目录」指到别处。
> 文件名见 `docs/packages/` 下对应文档的「基本信息」表。

## 二、配置界面

### 基本配置

| 项 | 说明 |
| --- | --- |
| **软件名称** | 默认 `auto-install`。用于生成默认安装根目录，同时作为日志与状态标识。不能包含 `\` `/` `:` 等路径字符。 |
| **安装根目录** | 默认 `%LOCALAPPDATA%\BJ\<软件名称>`（`BJ` 为公司名称）。可手动修改，或点「浏览...」选择目录。旁边「默认」按钮可恢复默认模板并重新跟随软件名称。 |
| **安装包目录** | 安装包所在目录，默认 `packages`。**可以填相对路径或绝对路径**（见下）。右侧「刷新」按当前目录重新扫描软件列表。 |
| **拷贝源目录** | 要部署到目标机器的资源文件夹（出厂文档、驱动等）。**留空则不执行拷贝**。 |
| **拷贝目标目录** | 拷贝源目录会被**整体**拷贝到该目录下的同名子目录。**留空则使用安装根目录**。 |
| **开机账户** | 左侧填**用户名**、右侧填**密码**（本地账户），默认 `admin` / `BJ88888888`。前置检查会确保该账户存在（不存在则创建）、属 `Administrators` 组（系统管理员）、密码可用且永不过期。密码以**明文**保存在 `config.ini`（该文件不入库）。用户名留空则跳过该项检查。 |

「基本配置」组下方有四行灰色提示，始终可见：

| 提示行 | 内容 |
| --- | --- |
| **实际路径** | 安装根目录把 `%LOCALAPPDATA%` 等环境变量展开后的真实路径，随输入实时刷新 |
| **安装包目录** | 安装包目录解析后的绝对路径（相对路径会拼到本程序所在目录下） |
| **日志文件** | 本次运行将要写入的日志文件完整路径 |
| **配置文件** | `config.ini` 的保存位置（固定不变，鼠标悬停可看完整路径） |

> 保存配置时，状态栏只提示「配置已保存」，具体保存到哪个文件看上面「配置文件」那一行即可。

> **关于自动跟随**：修改软件名称时，安装根目录会自动同步；一旦你手动改过安装根目录，
> 就停止跟随，避免覆盖你的输入。点「默认」可重新开启跟随。

> **关于环境变量**：安装根目录保存的是**含环境变量的模板**（如 `%LOCALAPPDATA%\BJ\auto-install`），
> 换机器、换账户后依然可用。也支持手工填入其它环境变量。

> **为什么用 Local 而不是 Roaming**：`%APPDATA%` 指向 Roaming 目录，会随域账户漫游同步到其它机器，
> 把安装文件放进去既拖慢登录、又可能造成版本混乱。`%LOCALAPPDATA%` 只属于本机，更适合放绿色工具、
> 日志等运行产物。基准位置由 `Include/Constants.au3` 的 `$ENV_INSTALL_BASE` 决定，改一行即可整体切换。

### 安装包目录：与项目解耦

**安装包目录**支持两种写法：

| 写法 | 示例 | 解析结果 |
| --- | --- | --- |
| 相对路径 | `packages` | `<本程序所在目录>\packages` —— 即「启动程序同级」，也是默认值 |
| 绝对路径 | `D:\装机包` | 原样使用 |
| 含环境变量 | `%USERPROFILE%\装机包` | 先展开环境变量再判断 |

所以可以把安装包放在完全独立的位置（比如移动硬盘、网络共享、另一个仓库），
程序本体和安装包互不绑定。

**切换安装包目录后会自动重新扫描**：点「浏览...」选好目录，或手动改完路径后点「刷新」，
软件列表会立即按新目录重填（窗口大小与控件位置都不变）。
**原来已勾选的软件如果在新目录里仍然存在，勾选状态会保留**；新出现的软件默认勾选。

### 资源拷贝（文档部署）

填了**拷贝源目录**后，执行时会多一项「拷贝资源」任务：

```
<拷贝源目录>   ->   <拷贝目标目录>\<源文件夹名>\
```

- 整个文件夹**原样搬过去**，目录结构完整保留。
- 目标是**覆盖式**拷贝（用 `robocopy /E` 实现），重复执行不会报错。
- 拷贝目标留空时，默认拷到**安装根目录**下。

例如源目录 `D:\出厂文档`、目标目录留空，结果是
`%LOCALAPPDATA%\BJ\auto-install\出厂文档\`。

> 拷贝源目录当前不存在时不会中断执行，日志里会记录一条错误并计入「失败」。

### 选择要安装的软件

软件列表由**安装包目录**下的子目录**自动扫描**得出，无需手工维护。
列表是一份带复选框的清单，点复选框即可勾选 / 取消，并按**分类分组**显示。

> **只有「已适配」的软件才会出现在列表里。**
> 判断依据是 `Include/Install/` 下有没有模块调用 `Installer_Register()` 注册了该目录名
> （见 [`development.md`](development.md) 的「新增一个软件」）。
> 安装包目录里尚未接入安装脚本的文件夹会被**自动忽略** —— 免得列出一堆点了也装不了的东西。
> 排障时想看看「哪些目录被忽略了」，把 `config.ini` 的 `[General] ShowUnsupported` 改成 `1`，
> 它们会以「显示名 (未适配)」出现在列表**最后**的「未适配（暂无安装脚本）」组里，且复选框固定不勾。

- 分组：每个软件归入哪个组，由它自己的 [`package.ini`](#packageini可选) 里的 `Category` 决定；
  分组头按 `Include/Constants.au3` 的 `$PKG_CAT_ORDER` 排列，「必须安装」组固定排第一，
  「未适配」组固定排最后。
- 工具条：**全选** / **全不选** / **反选**，右侧显示「已选 N / M」计数。
- 列表**高度固定**（约 6 行），软件多了由列表自带的**滚动条**浏览 ——
  窗口大小和控件位置都不会随软件数量变化。分组头也占行，所以组多时要往下滚。
- 安装包目录下没有**任何已适配**的软件时，列表里会显示一行灰色提示。
- 每个条目显示的是软件的**显示名**（来自 `package.ini` 的 `DisplayName`，没有则用目录名）；
  当前解析出的安装包绝对路径见上方「安装包目录」那一行灰色提示。

### 分组与「必须安装」

分类写在每个软件自己的 `package.ini` 里，配置界面只负责读出来分组显示。

| 分组键 | 界面显示 | 说明 |
| --- | --- | --- |
| `required` | 必须安装 | `Required=1` 的软件固定归入此组，**始终排在最前** |
| `base` | 基础环境 | 运行库、命令行工具等 |
| `dev` | 开发工具 | 编辑器、数据库客户端等 |
| `debug` | 调试工具 | 通讯调试、抓包、排障类工具 |
| `vision` | 机器视觉 | HALCON 等机器视觉（Machine Vision）专用软件 |
| `office` | 办公软件 | — |
| `misc` | 未分组 | 没写 `Category` 时的兜底分组，**没有分组的软件都归到这里** |
| `unsupported` | 未适配（暂无安装脚本） | **不是**从 `package.ini` 读的：没有对应安装脚本的目录会自动归入此组，固定排最后，仅在 `ShowUnsupported=1` 时可见 |

> 分组键与中文显示名的对应关系在 `Include/Config/Group.au3` 的 `Config_CategoryName()`；
> 想增删分组或调整先后，改 `Include/Constants.au3` 的 `$PKG_CAT_ORDER` 与那个函数即可。

**「必须安装」是锁定项**：

- 固定归入「必须安装」组并排在最前，不受 `Category` 影响；
- 列表里**强制勾选，点不掉** —— 点掉后会被自动补回来（约 60ms）；
- **全不选**、**反选**都跳过它；`config.ini` 里手改成 `0` 也没用，扫描时会被拉回 `1`。

> 所以出厂必装的软件（如 7-Zip）标上 `Required=1`，就能保证任何操作员都漏装不了。

### 底部操作

| 按钮 | 行为 |
| --- | --- |
| **开始安装** | 校验并保存配置，然后进入执行界面，按勾选项依次执行 |
| **保存配置** | 只保存到 `config.ini`（路径见「基本配置」组内的「配置文件」一行），不执行安装 |
| **退出** | 关闭窗口，不保存 |

左下角显示当前权限状态（管理员 / 普通用户），鼠标悬停可看说明。

## 三、命令行参数

| 参数 | 说明 |
| --- | --- |
| 无参数 | 打开配置界面（默认） |
| `--run` | 跳过配置界面，直接按 `config.ini` 执行安装 |
| `--auto-close` | 配合 `--run` 使用，执行结束后自动关闭，适合无人值守 / 批处理调用 |
| `--help` | 显示帮助 |

示例：

```bat
auto-install.exe --run --auto-close
```

**退出码**：全部成功为 `0`；存在失败项为 `1`。可在批处理里据此判断。

> 无人值守模式下（`--run`）不会弹出提权询问，请提前确保以管理员权限运行。

## 四、权限与提权

- 部分软件需要写入 `Program Files`、注册表或系统 `PATH`，**需要管理员权限**。
- 配置界面本身不需要管理员权限，只有在点「开始安装」时才会检查。
- 若检测到未提权，会弹窗询问是否以管理员身份重新启动：
  - 选「是」：先保存配置，再以 `runas` 方式带 `--run` 参数重启，自动继续执行；
  - 选「否」：以当前权限继续执行，日志中会给出警告，部分任务可能失败。
- 无人值守模式（`--run`）下不弹窗，直接以当前权限执行并在日志中记录警告。

## 五、配置文件

### config.ini

位于脚本同级目录，**首次运行自动生成**。

```ini
[General]
SoftwareName=auto-install
InstallRoot=%LOCALAPPDATA%\BJ\auto-install
PackagesDir=packages
CopySourceDir=
CopyDestDir=
ShowUnsupported=0

[Packages]
7zip=1
DBX=1
everything=1
halcon=1
HslCommunicationDemo=1
SQLite3=1
Sublime Text=1
wps=1

[Account]
UserName=admin
Password=BJ88888888
```

> `[Packages]` 里的键是**安装包目录下的子目录名**（不是显示名、也不是分组名），
> 顺序由扫描结果决定。上面的 8 项即当前 `packages/` 下的实际目录。
> 它们的分组显示为：必须安装（7-Zip、Everything）、基础环境（SQLite3）、
> 开发工具（Sublime Text、DBX）、调试工具（HslCommunicationDemo）、
> 机器视觉（HALCON）、办公软件（WPS Office）。
> **只有已适配（有安装脚本）的目录才会写进这一段**，未适配的目录不占键位。

| 段 / 键 | 说明 |
| --- | --- |
| `[General] SoftwareName` | 软件名称 |
| `[General] InstallRoot` | 安装根目录（可含环境变量的模板） |
| `[General] PackagesDir` | 安装包目录；相对路径相对本程序解析，默认 `packages` |
| `[General] CopySourceDir` | 资源拷贝源目录；留空表示不拷贝 |
| `[General] CopyDestDir` | 资源拷贝目标目录；留空表示用安装根目录 |
| `[General] ShowUnsupported` | 是否在软件列表里显示**未适配**（没有安装脚本）的目录，默认 `0` 不显示；排障时改成 `1` |
| `[Account] UserName` | 开机账户用户名（本地账户），默认 `admin`；留空则跳过前置检查中的账户检查 |
| `[Account] Password` | 开机账户密码，默认 `BJ88888888`；**明文**保存，`config.ini` 本身不入库 |
| `[Packages] <目录名>` | 该软件是否默认勾选，`1` 勾选 / `0` 不勾选。**标了「必须安装」的软件无效**，扫描时一律按 `1` 处理 |

- `[Packages]` 段由**安装包目录**的扫描结果自动维护，**新增软件会自动以 `1` 出现**。
- 也可以直接编辑本文件做批量预设，例如把 `wps` 改成 `0` 让它默认不勾选。
- 「必须安装」的软件（`package.ini` 里 `Required=1`）改这里也没用，界面与扫描都会把它拉回勾选。
- 想恢复默认，删除 `config.ini` 即可（`[General]` 里只有 `SoftwareName` 是必填的，其余留空即用默认值）。

### package.ini（可选）

在**安装包目录**下的 `<软件目录>/` 里放一份 `package.ini`，可指定配置界面里显示的名称、
所属分组、以及是否必须安装。三项都可以省略：

```ini
[Package]
DisplayName=WPS Office    ; 显示名，省略则用目录名
Category=office           ; 分组键，省略归入「未分组」
Required=0                ; 1 = 必须安装（固定归入「必须安装」组，且不可取消勾选）
```

| 键 | 取值 | 省略时 |
| --- | --- | --- |
| `DisplayName` | 任意文字 | 用目录名 |
| `Category` | `required` / `base` / `dev` / `debug` / `vision` / `office` / `misc` | 归入「未分组」 |
| `Required` | `1` / `0`（也认 `true` / `yes` / `on`） | 按 `0` 处理 |

> **⚠️ `package.ini` 必须保持 ASCII、不要带 BOM。**
> AutoIt 的 `IniRead` 是按 **ANSI 代码页**读无 BOM 文件的，实测：
> 中文值存成 UTF-8 会被读成**乱码**；存成 UTF-8 **带 BOM** 更糟 ——
> 连 `[Package]` 段都读不到，`DisplayName` 直接回落成目录名。
> 所以中文显示名统一放在 `Include/Config/Group.au3` 的 `Config_CategoryName()` 里，
> `package.ini` 只写上面的 ASCII 键值。
> （文件里的中文**注释**不受影响，注释在 `;` 之后，不参与解析。）

**新增一个分组**要改三处：`Include/Constants.au3` 的 `$PKG_CAT_ORDER`（排位置）、
`Include/Config/Group.au3` 的 `Config_CategoryName()`（定中文名）、
以及各软件 `package.ini` 里的 `Category`。

> `Category` 填了表里没有的值时不会被丢掉 —— 它按原样当成一个自定义分组名排在最后。
> 但那种情况下**分组名不能是中文**（原因见上面的编码说明），除非把 ini 存成 ANSI/GBK。
> 需要中文分组名就走「新增一个分组」的正路。

## 六、前置检查

点「开始安装」后、真正安装软件之前，程序会先做一遍**前置检查**，确认目标机器满足出厂交付的基本条件。
检查结果全部写入执行日志；能在程序内修好的（防火墙、电源、账户）会**自动修好**，
修不了的（家庭版、驱动异常）只做报告。

| # | 检查项 | 程序做什么 | 不通过时 |
| --- | --- | --- | --- |
| 1 | **系统版本** | 记录产品名、内部版本号、架构，并判断是否家庭版 | 家庭版会提示「不支持远程桌面主机等功能」，需人工确认 |
| 2 | **ping 与远程桌面** | 放通 ICMPv4 回显（ping）；开启远程桌面并放通 TCP 3389 | 记录警告 |
| 3 | **电源设置** | 把睡眠 / 休眠超时全部设为「从不」（交流 + 电池） | 记录警告 |
| 4 | **设备驱动** | 枚举设备管理器中存在问题的设备（感叹号），列出名称与错误码 | 记录警告，需人工到设备管理器处理 |
| 5 | **开机账户** | 确保配置里的本地账户存在（不存在则创建）、属 `Administrators` 组、密码可用且永不过期。密码策略**设置后回读确认**，不通过会明确报错 | 记录警告，需人工处理 |

**会改动系统的检查项（第 2、3、5 项）会打印「更改前 / 更改后」两行状态**，方便核对到底改成了什么，例如：

```
[INFO ]   [更改前] 睡眠：交流 15 分钟 / 电池 10 分钟；休眠：交流 30 分钟 / 电池 30 分钟
[INFO ]   [更改后] 睡眠：交流 从不 / 电池 从不；休眠：交流 从不 / 电池 从不
[INFO ]   [更改前] 「admin」账户不存在
[INFO ]   [更改后] 「admin」账户存在（已启用，在 Administrators 组（系统管理员），密码永不过期）
```

只读的检查项（第 1 项系统版本、第 4 项设备驱动）没有改动，因此只输出一次状态。

> **读不出状态会明确报错**：如果某项状态读不出来（例如 `powercfg` 输出格式与预期不符），
> 程序会记一条警告并把它计入问题清单，**不会悄悄放过** —— 前置检查必须能明确知道改前改后的状态。
> 遇到这种情况请把日志发出来排查。

**发现问题时怎么办**（由 `Precheck_RunAll()` 的交互参数决定）：

- **交互模式**（直接运行，或 `--run` 不带 `--auto-close`）：把问题汇总成一个对话框，
  由操作员选「是」继续安装 / 「否」中止安装。选「否」时**不会执行任何安装任务**，程序以退出码 `1` 结束。
- **无人值守模式**（`--run --auto-close`）：只记录警告，不弹窗、不打断流程，继续执行安装。

> **为什么家庭版要单独确认**：Windows 家庭版没有远程桌面**主机**（只能作为客户端连出去），
> 也没有组策略与域加入 —— 工控机常见的远程运维、批量管理手段都用不了。所以检测到家庭版时
> 会明确提示，由现场决定是否继续。

> **关于防火墙规则**：程序添加的是**自建规则**（`auto-install ICMPv4-In`、`auto-install RDP-TCP-In`），
> 不用系统内置规则的名称 —— 内置规则名（组名）随系统语言变化，引用不可靠。
> 每次执行会先删除同名旧规则再添加，不会越堆越多。

> **关于开机账户**：默认 `admin` / `BJ88888888`（常量 `$ACCT_DEF_USER` / `$ACCT_DEF_PASS`，
> 见 `Include/Constants.au3`），可在配置界面或 `config.ini` 里改。只管理**本地账户**：
> 填成域账户或微软账户（含 `@` 或 `\`）时只做提示，不会创建。账户会被加入 `Administrators` 组
> （系统管理员），并按需启用、设置密码永不过期；密码以**明文**保存在 `config.ini`。
> 密码请**不要包含 `;`**（INI 注释符，读回时会被截断）与英文双引号（会破坏命令）。
>
> **「密码永不过期」是怎么设的**（这里踩过坑，说明一下）：
> 程序先执行 `net accounts /maxpwage:unlimited` 设全局策略，再尝试 PowerShell 的
> `Set-LocalUser -PasswordNeverExpires $true` 设该账户的 per-user 标志，**然后回读确认**
> （重试若干次，等策略传播）。两条路都没生效时**会如实报错**（`[WARN]` + `[ERROR]`），
> 不会像旧版本那样只查「账户是否存在」就打 `[OK]`。
>
> 注意：`Set-LocalUser` / `Get-LocalUser` 属于 PowerShell 的 **LocalAccounts 模块**，
> **部分精简版 / 老旧 Win10 工控机上并未安装**，调用会报
> 「无法将"Set-LocalUser"项识别为 cmdlet…」并返回退出码 `1`。这是**预期情况**，程序会自动
> 走全局策略这条回退路；若回退后仍读到「密码会过期」，就属于**该机环境限制，需要人工处理**
> （例如用 `gpedit.msc` 或直接改账户属性）。判定依据是 **WMI `Win32_UserAccount.PasswordExpires`**，
> 它读的是该账户的 per-user 标志，与 `net user` 里「密码到期」一行含义一致。

> **前置检查需要管理员权限**：开启远程桌面、改防火墙、改电源计划、创建账户都要写系统。
> 未提权时按第四节的流程处理。

## 七、执行日志

- **位置**：`<安装根目录>\logs\install_<时间戳>.log`，UTF-8 编码。
- **内容**：每行形如 `[2026-10-06 19:06:54] [INFO ] 消息`，级别有
  `INFO` / `OK` / `WARN` / `ERROR` / `STEP`。
- 执行界面上的日志框会**实时**同步显示同样的内容，点「打开日志目录」可直接定位到日志所在文件夹。

### 界面上的日志按级别着色

执行界面的日志框是 **RichEdit** 控件，不同级别显示成不同颜色，扫一眼就能看到问题在哪：

| 级别 | 颜色 | 用在哪 |
| --- | --- | --- |
| `INFO` | 深灰 | 常规信息、分隔线 |
| `OK` | 绿 | 处理完成的项 |
| `WARN` | 橙 | 警告（不打断流程，但值得注意） |
| `ERROR` | 红 | 失败项 |
| `STEP` | 蓝 | 阶段标题（`1/5 系统版本…`、`开始安装「xxx」`） |

颜色在 `Include/Constants.au3` 的 `$LOG_COLOR_*` 里改（**RGB 写法**）。
日志**文件**里仍是纯文本，不带颜色。

> 每一行是**整行同色**（从行首的 `[` 一直到行尾），不会出现「半截变色」或「从某一行开始
> 颜色错位」。这一点是特意保证的 —— RichEdit 对「字符位置」有好几套不同口径，早期版本
> 用错口径导致逐行累积偏移、日志串色，现已改为每次追加后用控件自己回读末尾位置来上色。
> 详见 [`docs/development.md`](development.md) 的「RichEdit 字符坐标系」。

### 等待心跳（界面长时间没动静 ≠ 卡死）

安装 / 解压 / 拷贝耗时较长时，程序**仍在正常工作**，只是那一步没有新内容可打印。
为便于观察，等待期间会持续输出心跳：

- 执行界面顶部的信息标签**每秒刷新**，显示如 `DBX 安装，已等待 3 分 20 秒 ...`；
- 日志里每 10 秒补一条 `XXX 仍在进行，已等待 3 分 20 秒`。

**只要计时还在往上走，就说明任务在正常执行，不必强行结束进程。**
界面在等待期间本身也是响应的（可以移动窗口、点「打开日志目录」），不会假死。

心跳间隔由 `Include/Constants.au3` 的 `$RUN_HEARTBEAT_MS`（界面刷新）与
`$RUN_HEARTBEAT_LOG_SEC`（写日志）控制。

### 结果汇总

执行结束时日志会给出汇总，执行界面顶部也会提示：

```
成功 N 项  |  跳过 M 项  |  失败 K 项
```

| 状态 | 含义 |
| --- | --- |
| **成功** | 安装/解压完成并通过结果校验；**已经装好、无需处理的也计入这里**（日志里会写「已检测到 X，跳过安装」） |
| **跳过** | 该软件尚未实现安装脚本（日志会提示需要补的模块名） |
| **失败** | 安装包缺失、启动失败、超时，或装完未通过结果校验 |

执行顺序是：**先按勾选依次安装软件，最后执行资源拷贝**（若配置了拷贝源目录）。
资源拷贝会作为一项独立任务出现在进度与汇总里。

> **一项都没勾选时也能执行**：不会中止，只在日志里记一条警告（`没有勾选任何要安装的软件…`），
> 然后照常走前置检查。此时若配了拷贝源目录，就只做资源拷贝这一项；
> 两者都没有则本次不执行任何任务，界面提示「没有需要执行的任务（未勾选任何软件）」。

### 已安装检测

每个软件在动手之前都会先判断是否已经装过，判断范围是：

1. 该软件的**预期安装路径**（如 `C:\Program Files\7-Zip\7z.exe`）；
2. **整个系统 `PATH`** —— 覆盖「装在别的盘 / 其它目录」或「绿色版已经挂在 `PATH` 上」的情况。

任一命中就视为已安装，直接跳过、不重复安装，并计入「成功」。日志里会打印实际找到的位置。

## 八、常见问题

**Q：点「开始安装」后弹出「前置检查发现 N 个问题」，该选哪个？**
选「是」继续安装、选「否」中止。选「否」时不会执行任何安装任务，日志里会写明原因。
可以先按对话框（或日志）里的提示逐项处理，再重新运行。

**Q：日志提示「系统为 Windows 家庭版」？**
家庭版不支持远程桌面主机、组策略、域加入等，工控机常用的远程运维手段用不了。
确认现场不需要这些功能，就在弹窗里选「是」继续；否则建议改用专业版 / 企业版系统。

**Q：日志提示「有 N 个设备驱动异常」？**
说明设备管理器里有带感叹号的设备（驱动未安装 / 无法启动等）。程序**只报告不修改**，
请按日志里列出的设备名与错误码，在设备管理器中手动安装或更新驱动后重新运行。

**Q：日志提示「未能完整开启远程桌面」？**
程序已尝试写入注册表并添加防火墙规则。若仍失败，请检查 Windows 防火墙服务是否被禁用，
或手动在「设置 - 系统 - 远程桌面」中开启。

**Q：开机账户的密码存在哪里？**
存在 `config.ini` 的 `[Account] Password`，**明文**，默认 `admin` / `BJ88888888`。
`config.ini` 本身不入库（见 `.gitignore`）。

**Q：点了「开始安装」但某个软件直接「跳过」了？**
该软件还没有对应的安装脚本。按日志提示在 `Include\Install\` 下补一个模块，并在 `All.au3` 的模块列表登记，见 [`development.md`](development.md)。

**Q：日志显示「安装超时，已强制结束」？**
单个软件默认超时 10 分钟（WPS 为 30 分钟）。安装包体积大或机器较慢时可能不够，
可在 `Include\Constants.au3` 中调整 `$TIMEOUT_INSTALL` / `$TIMEOUT_INSTALL_LONG`。

**Q：某个软件安装了很久，界面没动静，是卡死了吗？**
通常不是。等待期间界面顶部会显示「XXX 安装，已等待 X 分 Y 秒 ...」并**每秒刷新**，
日志里每 10 秒也会补一条「仍在进行」。**计时在走 = 程序在工作**。
真正卡死的表现是：计时**停止不动**、窗口无法移动、点按钮没反应 —— 那才需要处理。

**Q：装完提示「未找到 xxx」？**
说明安装程序返回了成功，但在**预期路径和整个系统 `PATH`** 里都没找到主程序。
请核对 `docs/packages/` 下该软件文档的「脚本实现」一节，以及安装包版本是否与脚本常量一致。

**Q：日志说「已检测到 X，跳过安装」，但汇总里算成了「成功」？**
这是正常的。已经装好的软件无需再处理，属于「处理完成」，所以计入成功；只有**没有安装脚本**的软件才计入「跳过」。

**Q：想换一个版本的安装包？**
替换安装包目录下 `<软件目录>/` 里的文件后，同步修改 `Include/Install/<软件>.au3` 顶部的安装包文件名常量，
并更新 `docs/packages/` 下对应的说明文档。

**Q：一个软件都没勾选，能点「开始安装」吗？**
能。一项都没勾选**不会中止**，程序照常进入执行界面并做完前置检查，只在日志里记一条警告
（`没有勾选任何要安装的软件，本次只记录日志。`）。
此时若配了拷贝源目录就只做资源拷贝；两者都没有则界面提示「没有需要执行的任务（未勾选任何软件）」。

**Q：软件列表是空的 / 少了几个软件？**
列表是扫描**安装包目录**下的子目录得出的，但**只列已适配的目录** ——
没有对应安装脚本（`Include/Install/` 下没调用 `Installer_Register()` 注册过该目录名）的会被自动忽略。
**一个已适配的都没有时，列表就是空白的**（只显示「已选 0 / 0」，不放任何占位行）。
排查顺序：

1. 看「基本配置」组里「安装包目录」那一行灰色提示，确认解析出的绝对路径对不对；
2. 确认该目录下确实有以软件名命名的子目录；
3. 确认这个子目录已经接入安装脚本（**目录名要与 `Installer_Register()` 的第一个参数完全一致**，
   并在 `Include/Install/All.au3` 里登记）；
4. 想确认「到底哪些目录被忽略了」，把 `config.ini` 的 `[General] ShowUnsupported` 改成 `1` 再看列表，
   被忽略的会以「显示名 (未适配)」出现在最后的「未适配（暂无安装脚本）」组里。

改完路径后记得点右侧「刷新」。

**Q：列表里出现了「(未适配)」的条目，还勾不上？**
说明 `config.ini` 的 `[General] ShowUnsupported` 被设成了 `1`。这类条目只是**占位提示**
（目录在、但没有安装脚本），复选框固定不勾、也不参与全选 / 反选，更不会被安装。
不想看到就把 `ShowUnsupported` 改回 `0`。

**Q：改了安装包目录，勾选会不会丢？**
不会。重新扫描时，**在新目录里仍然存在的软件会保留原来的勾选状态**，新出现的软件默认勾选。
但标题是「必须安装」的软件无论如何都是勾选的。

**Q：为什么有的软件取消不掉勾选？**
它在 `package.ini` 里标了 `Required=1`，属于**必须安装**项，勾选被锁定：
点掉会自动补回来，全不选 / 反选也会跳过它，改 `config.ini` 同样无效。
要解除就把那个 `Required` 改成 `0`（改完点「刷新」）。

**Q：软件的显示名 / 分组不对，或者全挤在「未分组」里？**
看该软件目录下的 `package.ini`：没写 `Category` 就会归入「未分组」，写的是表里没有的键就排到最后。
还有一个常见原因是**文件编码** —— 中文写进 `package.ini` 必须存成 ANSI/GBK，
存成 UTF-8 会被读成乱码、带 BOM 则整段读不到（详见 [package.ini 一节](#packageini可选)）。
改完 `package.ini` 后在配置界面点「刷新」重新扫描。

**Q：列表里的分组名是中文，会不会在英文系统上变乱码？**
不会。分组头的文字是按 Unicode 直接写给控件的，与系统区域设置无关。

**Q：拷贝资源没执行？**
「拷贝源目录」留空就不会执行。填了之后，日志里会出现一项「拷贝资源」任务，
写明了源目录与目标目录，可以据此核对。
