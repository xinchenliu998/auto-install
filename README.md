# auto-install

> 基于 **AutoIt** 的工控机出厂前自动化工具集 —— 统一完成软件安装、文档部署与各类重复性操作，让每台出厂的工控机保持一致、可复现的环境。

---

## 项目简介

工控机（IPC）在出厂前需要统一安装一批常用软件、运行库和配套文档，此外还有大量**重复性的手工操作**（如系统设置、文件拷贝、环境配置、清理等）。人工逐台处理不仅效率低，还容易出现版本不一致、漏装、误装、配置遗漏等问题。

本项目通过 AutoIt 编写自动化脚本，把「软件安装 + 文档部署 + 重复性操作」封装为可重复执行的流程，实现：

- **统一**：所有出厂设备软件版本、安装路径、配置项完全一致。
- **高效**：一次配置，批量执行，显著缩短单台处理时间。
- **可追溯**：脚本、文档、软件版本清单一并纳入版本管理，处理内容一目了然。
- **易扩展**：新增软件或操作只需补充对应脚本，无需改动整体框架。

### 适用范围

| 类型 | 说明 | 示例 |
| --- | --- | --- |
| 软件安装 | 批量安装常用软件、运行库 | 7-Zip、WPS、Sublime Text 等 |
| 文档部署 | 拷贝出厂文档、说明书到指定目录 | 产品手册、驱动、说明文件 |
| 前置检查 | 安装前确认系统条件，可修的自动修好 | 系统版本、ping 与远程桌面、电源计划、驱动状态、开机账户 |
| 重复性操作 | 将固定、重复的手工步骤脚本化 | 系统设置、环境配置、目录清理、注册表项、快捷方式等 |

> 项目名称取自「自动化安装」，实际覆盖范围不限于安装包，凡属出厂前的**重复性操作**均可纳入本工具集。

## 目录结构

```
auto-install/
├── auto-install.au3    # 总入口脚本：配置界面 + 安装调度
├── config.ini          # 运行配置（首次运行自动生成，不入库）
├── .gitignore          # 忽略安装包、运行产物、编译产物等
├── AGENTS.md           # 面向 AI 编码助手的开发约定
├── CLAUDE.md           # 同上（Claude 入口，指向 AGENTS.md）
├── docs/               # 项目文档
├── Include/            # AutoIt 脚本：框架模块 + 界面层 + 各软件安装脚本
├── packages/           # 各软件的安装包（整个目录不入库）
└── tools/              # 辅助脚本：语法检查 + 源码静态自检 + 文档一致性检查 + 前置检查冒烟测试
```

> 详细的目录与模块说明见 [`docs/development.md`](docs/development.md)。

## 环境要求

- **操作系统**：Windows 10 / 11（建议 Windows 10 x64 及以上）
- **运行环境**：AutoIt v3（开发调试用），或使用编译后的独立可执行文件（无需安装 AutoIt）
- **权限**：安装脚本需以**管理员权限**运行，以便写入系统目录与注册表

## 快速开始

1. 把整个项目拷贝到工控机本地目录（建议非系统盘，如 `D:\auto-install`）。
2. 把各软件的安装包放进 `packages/<软件名>/` 对应目录。
3. 运行 `auto-install.au3`（或编译后的 `auto-install.exe`）。
4. 在配置界面设置**软件名称**、**安装根目录**（默认 `%LOCALAPPDATA%\BJ\<软件名称>`）、
   **安装包目录**（默认本程序同级的 `packages`）、**开机账户**（默认 `admin` / `BJ88888888`，
   前置检查会确保它存在、可用且是系统管理员）；需要一并部署出厂文档时，
   再填**拷贝源目录 / 拷贝目标目录**。最后勾选本次要安装的软件。
5. 点击「开始安装」，等待执行完成，根据日志核对结果。

> **安装包目录不纳入版本管理**：整个 `packages/` 目录都不进 git —— 安装包体积普遍较大，
> 部分单个安装包就超出代码托管平台的单文件上限；而且该目录本身可配置、可以放在仓库之外。
> 克隆仓库后需自行创建该目录并放入安装包，或在配置界面把「安装包目录」指到别处。
> 各软件需要的文件名见 [`docs/packages/`](docs/packages/) 下对应文档的「基本信息」表。

> 提示：首次使用前请先在测试机上完整跑一遍，确认静默安装参数与目标系统匹配。
